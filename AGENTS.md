## 1) Project-specific instructions

**Project:** `ucrc`
**Primary goal:** A C11 CRC-8, CRC-16 and CRC-32 library for embedded systems, with a runtime model descriptor, a compile-time strategy, no allocation and no mutable state.

### 1.1 Essential commands

#### Configure and build (library only)

```sh
meson setup build --wipe --buildtype=release -Dbuild_tests=false
meson compile -C build
```

#### Configure, build, and run unit tests

```sh
meson setup build --wipe --buildtype=debug -Dbuild_tests=true
meson compile -C build
meson test -C build --verbose
```

#### Regenerate the committed tables

```sh
meson compile -C build regen-tables
```

#### MISRA C:2023 (reads `build/compile_commands.json`)

```sh
misch run
```

#### Formatting (pinned clang-format through `uvx`)

```sh
scripts/format.sh          # check, as CI does
scripts/format.sh --fix    # rewrite in place
```

### 1.2 Notes

- `include/ucrc.h` defines the version macros, and `meson setup` fails when they differ from `project(version:)`, so a release updates both. `include/ucrc_version.h` is a deprecated header that includes `ucrc.h`.
- Configuration is by macro (`UCRC_ENABLE_CRC*`, `UCRC_STRATEGY`, `UCRC_ASSERT`) with defaults in `ucrc_conf.h`; there are no Meson options beyond `build_tests`.
- The test suite is modular: `tests/test_harness.c` holds the runner, `tests/test_support.c` the model list, PRNG and independent reference engine, and each category module exposes `run_<category>_tests()` for `tests/test_main.c`.

## 2) Non-negotiable design invariants

- Every strategy and the 16-bit-MAU simulation give the published check value for every predefined model, and agree with the independent reference engine.
- The bitwise engine is always compiled and serves every model whose `table` is `NULL`.
- `src/ucrc_tables.c` is generated by `tools/gen_tables.c` and committed. Never edit it by hand, never format it, and keep the generator deterministic.
- Only the low 8 bits of each `ucrc_octet_t` are read; octets and table indices are always masked.
- No public function invokes undefined behaviour on a `NULL` pointer or a zero length, with `UCRC_ASSERT` enabled or compiled out.
- No heap, no recursion, no mutable global state. The caller carries the running value.

## 3) CI / source of truth

- CI definitions live in `.github/workflows/ci.yml`.
- Prefer running the same commands locally as CI runs (see §1.1 above).
- Install Python tools (Meson, Ninja, gcovr, misch) with `uv tool install`, never `pip`; CI does the same through `astral-sh/setup-uv`.
- The CI jobs are: tests under ASan/UBSan, every strategy against every width combination with warnings as errors, an Arm Cortex-M0 freestanding compile, a release build, a TI C2000 library build (CGT 22.6.2 and 25.11.1, COFF and EABI, warnings as errors), `clang-format`, a 100 percent line and 87 percent branch coverage gate, and `misch` against the recorded deviations.

## 4) Docs / commit conventions

### Documentation layout

- `README.md` is a short landing page (about 70 lines). Put detail in `docs/`, never in the README; link to the owning file instead.
- `docs/integration.md` owns requirements, install methods, configuration macros, building, and cross builds.
- `docs/api.md` owns the API reference. Change it together with `include/ucrc.h`; keep signatures in fenced `c` blocks and describe them in prose, not function tables.
- `docs/design.md` is the single authoritative design record.
- `CONTRIBUTING.md` documents the contributor workflow; `CHANGELOG.md` holds release history; `.github/SECURITY.md` covers vulnerability reporting.
- Code blocks in `README.md`, `CONTRIBUTING.md`, and `docs/` are compiled by the `ucrc docs examples` test (`tests/docs/check_snippets.py`). Each document is compiled as one source file: a `c` fence is file-level code, `<!-- snippet: body -->` wraps statements, and `<!-- snippet: skip -->` excludes pseudo-code. Do not use `skip` to silence a broken example.
- Prose uses British spelling. Do not hard-wrap Markdown: write one line per paragraph. The 80-column limit applies to C source, not Markdown.

### Commits

- Use **Conventional Commits** format when asked to commit.
- Keep commits focused; explain *why* in the message body.

## 5) C style expectations

### Build & configuration

- Use the Meson build system. Do not introduce CMake, Make, or other systems.
- Update `meson.build` and `tests/meson.build` when adding or removing files.

### Formatting

- `.clang-format` is present and **mandatory**. Run `scripts/format.sh --fix` before committing. It runs the clang-format release pinned in the script through `uvx`. Do not use a system `clang-format`: another release can format the same code differently.
- Do not reformat unrelated code.
- Key settings: 8-space indent, `BreakBeforeBraces: Linux`, column limit 80.

### Style & correctness

- Match conventions in the existing files (indentation, braces, naming).
- Keep public headers minimal and stable.
- Use fixed-width types from `<stdint.h>` and `<stdbool.h>`; octets are `ucrc_octet_t`, never `uint8_t`.
- Every new MISRA deviation is recorded in `misra-deviations.txt` or inline, and in the deviation record in `src/ucrc.c`.

### Error handling

- Preconditions go through `UCRC_ASSERT`, followed by a defensive return that keeps the call defined when the assertion is compiled out.
- No `errno`; no exceptions.

### Comment placement (Doxygen)

- Inline trailing annotations (`/**< ... */`) on `enum`/`struct` members are allowed only when the resulting line fits the 80-column limit.
- If any member's annotation would overrun, move **all** of that aggregate's member docs into a single structured Doxygen block above the type, as an `@details` list of `- ::SYMBOL  description` entries.
- Never mix inline and block forms within one aggregate, and never leave a trailing comment that clang-format would wrap onto a second line.
- After editing, run `scripts/format.sh` and an 80-column scan.

### Testing

- Run `meson test -C build` after every change.
- Add a test case for each bug fix, checked against a published check value or the reference engine.
- In tests, never use `sizeof(array)` as an element count; `ucrc_octet_t` is 16 bits under the simulation.
- Keep `src/` and `include/` at the coverage gate (100 percent line, 87 percent branch).
